# Clipper deep audit and SaaS suitability

**Classification: B — partial.** A local FastAPI control API and durable native pipelines exist, but there is no customer-safe remote job service. At audit time the documented backend :8765 and Vite :5173 were offline. AI Site's `/clipper` only calls a sanitized, read-only overview; its “Open Clipper” is an external localhost link. No upload, control token handoff, tenant isolation, cloud artifact output, or AI Site job submission exists.

## Current standard path

`D:\VOD` watched file / CLI `main.py --video` / local `POST /api/control/queue` with `single_video` and a video path constrained to watched input → `video_queue.py`/supervisor stage queues → `transcriber.py` Faster-Whisper, optional WhisperX word alignment → canonical `working/artifacts/transcripts/<artifact-id>/` plus run reference/legacy `transcript.json` → `transcriber.build_text_chunks` → `moment_detector.detect_moments` using local LM Studio OpenAI-compatible :1234, producing `moments.json` → optional YOLO `vision_scanner` → variants and `main._build_clip_job` / `_process_clip_job` → `ffmpeg_editor` cut/render/captions, compliance and `clip_scorer` → `D:\output_clips/<run>/manifest.json`, scored sidecars, output tiers and optional export package. Current moment prompt is PROYA/Indonesian skincare-specific; do not use it for arbitrary customers. Transcript schema version is 3 with segment/word timestamps and metadata; moment objects carry start/end/score/hook/reason/product/type/category. Score records and manifests form distinct later scoring data, not the same as initial LLM moment score.

## Alternative modular path

Modular Scanner (`modular_library.sqlite3`) records source and transcript generations/ranges → Planner (`modular_planner.sqlite3`) drafts compositions and freezes approved source/range snapshots → Renderer (`modular_renderer.sqlite3`) materializes base MP4 → transcript bridge maps word times → production (`modular_production.sqlite3`) runs variants, compliance/scoring/export. It shares downstream variant and FFmpeg functions with standard. Both paths are native, with their own recovery rules; the initial SaaS worker should choose one explicitly and avoid pretending they share one simple schema.

## API, queue, persistence, recovery

- Backend `clipper_app/web_api.py` exposes safe summaries `GET /api/health`, `/api/queue`, `/api/queue/vods`, `/api/scores`, dashboard/overview and other routes; sensitive GETs and all writes require per-process bearer `CLIPPER_CONTROL_TOKEN` under `application/api_security.py`, plus local host/origin checks. Electron `new_app/electron` can launch a child backend with fresh token; that token is not a stable remote worker credential. `POST /api/control/queue` submits a control job, and `/api/control/jobs/:id` reads it. Modular production has separate `POST /api/modular-production/jobs` and read/continue/cancel routes. Control jobs are bounded metadata/result files under `working/app_control_jobs` and `app_control_job_results`, not a tenant queue.
- Standard queue `video_queue.py` uses staged GPU, YOLO, and FFmpeg queues, a supervisor, `working/video_queue_state.json` by default or SQLite opt-in, stage fingerprints, checkpoints, retry-failed options, and atomic output publication. `running` persisted status alone does not prove liveness. Generic FastAPI control jobs mark stale queued/running operations interrupted on startup rather than replaying mutations. Modular services have distinct SQLite recovery and cooperative cancellation.
- Native authoritative stores include `working/catalog/clipper.sqlite3`, `modular_library.sqlite3`, `modular_planner.sqlite3`, `modular_renderer.sqlite3`, `modular_variant_pilot.sqlite3`, `modular_production.sqlite3`, `working/artifacts/artifact_registry.sqlite3`, queue JSON/optional SQLite, run manifests/sidecars, and `D:\output_clips`. None is safe to reinterpret as workspace-owned SaaS Postgres. Clipper's README/docs and source were inspected; database contents were not modified or queried.

## Why API is insufficient as-is

The control API expects a local path in `D:\VOD`, depends on an operator-launched process and per-process token, and returns native job/output identities. It cannot accept signed cloud source assets, maintain SaaS leases, attach workspace and product snapshots, report durable cloud progress, or guarantee isolated customer outputs. The AI Site adapter `app/src/lib/integrations/clipper/index.ts` intentionally strips paths and reads only health, queue, VOD names and score summaries. The submission request model in `submission.ts` has no route. Thus “Clipper Offline/Checking” means the local API was unavailable at page load; it is not evidence that an upload or job completed.

## Extraction/wrapping plan

Extract a headless **single-source operation** around transcription, moment plan, render, validation, and artifact manifest. Keep proven transcript cache/fingerprint logic and FFmpeg/caption pipeline; replace fixed PROYA prompts/assets/settings with versioned workspace input and a provider-neutral transcript analyzer. Run this inside a private Windows worker that claims SaaS jobs outbound over TLS, downloads source to an isolated per-job directory, executes one bounded native pipeline, uploads validated clips, and posts completion with a lease fencing token. Do not expose FastAPI or the processing PC to customer browsers. Do not write into current Clipper queues/databases during Phase 0; first implementation should run against a separate staging clone and controlled fixture.

### Future transcript analyzer

`TranscriptAnalyzer.analyze({transcriptVersion, language, productSnapshot, goals, chunk, policyVersion}) -> {candidates, usage, modelVersion}`. Supply timestamped transcript plus metadata, not a full raw video. Chunk by token budget with overlapping time windows; normalize timestamps to source time; collect candidate spans; dedupe by overlap/semantic similarity; globally rank against diversity and budget; validate `0 <= start < end <= sourceDuration`, min/max clip length, speech boundaries, and requested count; then render. A structured plan has `{clips:[{start,end,score,hook,reason,tags}], analyzerVersion, transcriptArtifactId}`. Preserve candidate evidence and token usage; retry transient LLM failures with an idempotent stage key, cap tokens/cost, and stop rather than fabricating clips when parsing/validation fails. Multimodal selection can be a later adapter only when transcript misses visual-only actions.

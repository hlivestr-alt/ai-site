# Internal Outreach boundary and future distribution

Current internal Outreach is **operational by source/integration design**, with Docker web/API and discovery/history/outbound workers running; this audit did not submit a campaign or call native campaign endpoints. AI Site's current `AUTH_ENABLED=false`, `OUTREACH_QUEUE_ENABLED=true`, and one-click campaign send are explicit internal choices. They do **not** define customer SaaS authentication or permission policy.

The AI Site `src/lib/integrations/outreach/*` adapter calls the native API on loopback. A send click creates a draft, runs discovery/preview, freezes recipients, confirms current version and sender availability, then invokes native `/send`. AI Site stores a small operation journal in `app/data/outreach-operations/`; native Outreach Postgres owns campaign/recipient/delivery/outbox state and BullMQ/Redis carries dispatch. The outbound worker alone sends through the internal account. Current source includes conditional state/version checks, recipient reservations, cooldown/exclusion behavior, deterministic delivery/outbox keys, pause/resume/cancel endpoints, and `DELIVERY_UNKNOWN` handling. Native create lacks a general idempotency key, so uncertain creation is not blindly retried. Some native GETs expire stale previews and therefore can write state; no native campaign GET was used during this read-only audit.

The current DB contains Creator, provider identity, metric/contact snapshots, Campaign, CampaignRecipient, OutreachDelivery, DeliveryAttempt, QueueOutbox, OutreachReservation, and dispatch events. Its Postgres is not the customer SaaS source of truth. Existing sender/account, crawler, DB and workers stay untouched through the first paid release.

Future Distribution is a later phase: each workspace owns an authorized channel integration, creator list, template, campaign, contact history and audit trail. Preserve Preview → Freeze → final Confirm as the action boundary, with platform Creator ID dedupe, cooldown/exclusions, rate limits, stop control, and unknown-delivery reconciliation. Never let customers use the shared internal sender or another workspace's account. Channel data is required before showing views, orders, GMV, ROI, creator results, or sales attribution; otherwise show **Not connected**. Reusing native algorithms requires a new tenant/account authorization boundary and separate review.

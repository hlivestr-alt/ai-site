# Security review

Sessions are opaque hashed tokens, HTTP-only, SameSite=Lax, path=/, expiring after 14 days, Secure when the configured origin is HTTPS. Logout revokes its session; password reset revokes active sessions. Pending/unverified users cannot sign in. Role and active-workspace checks remain authoritative on every customer resource; composite workspace/lineage constraints remain unchanged.

Customer state-changing requests require the exact configured Origin. Webhooks are the deliberate exception and authenticate the provider token/signature over bounded raw bytes; worker callbacks require an outbound worker bearer plus lease/fencing identity. JSON request bodies are bounded to 16 KiB during streaming even with a false/missing Content-Length; webhook streaming is bounded to 64 KiB. Media bypasses application JSON limits through scoped storage uploads.

The request proxy adds a fresh CSP nonce and request ID. Dynamic rendering preserves nonce consistency. Production scripts use nonce/strict-dynamic without unsafe-eval; images/media/connect allow self plus explicitly configured storage origins; object/frame embedding is denied. Style inline remains permitted for existing React styling. X-Frame-Options DENY, nosniff, no-referrer, restricted Permissions-Policy and production HTTPS HSTS accompany responses. Do not add arbitrary customer URLs to CSP.

Vendor bucket privacy/CORS is a separate production gate: block public access/listing, use scoped IAM credentials, allow only the SaaS origin and GET/PUT/HEAD with needed headers, and test browser upload/video playback. Local signed-gateway tests prove deterministic signature/unsigned access behavior, not vendor policy. Signed media is not stored in database snapshots, audit metadata or logs and is not a public static URL.

Secret inventory: PostgreSQL credential; storage access/secret; BytePlus API key; private worker bearer/OpenAI key; Xendit sandbox API/callback/business identity; SMTP password/mail key; restricted readiness token. Keep them in protected runtime files/secret management, never source or general logs. Rotate storage/API/SMTP/readiness credentials through provider-managed overlapping keys where possible; revoke worker credentials using the existing worker-admin rotate command; drain safely and verify recovery. Retain necessary old decryption keys with encrypted backup custody.

Production payment credentials remain disallowed by the existing sandbox adapter. Fake providers/test catalogs/diagnostics require explicit nonproduction gates. Critical paths keep external provider/payment/multipart/media-byte work outside DB transactions and revalidate identity before committing; bounded metadata checks remain inside fenced claims. Pool connection/statement/lock/idle transaction limits are explicit and do not constrain migration/backup connections.

Customer failure boundaries show retryable safe messages/support references. Operator APIs expose bounded safe records and require separate allowlist authorization. Deterministic tests check role isolation, wrong Origin, oversized bodies, persistent 429, headers/cookies, private media and unavailable dependencies. Public HTTPS, real sender delivery, production bucket policy and actual external services remain unverified until conditional acceptance.

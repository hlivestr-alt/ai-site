# Local development and acceptance

Apply the Phase 4 migration with `npm run db:migrate`; `npm run test:schema-bootstrap` verifies a clean 0001–0004 install. Configure isolated Postgres and private S3-compatible buckets as in the Phase 3 setup. The `.env.example` file contains provider placeholders. Keep API keys only in local or managed secrets, never in Git or Job snapshots.

For nonbillable tests, set `APP_ENV=local`, `VIDEO_PROVIDER=fake`, and `ENABLE_FAKE_VIDEO_PROVIDER=1` for both Next.js and the dispatcher. Playwright's configuration sets these for its test app. Run `npm run test:browser`, `npm run test:video-restart`, `npm run test:restart`, `npm run lint`, `npm run typecheck`, and `npm run build`. The fake provider uses the committed tiny MP4 fixture. Its simulation label is visible in Create Video. Production mode cannot enable the fake provider.

For one real acceptance generation, set `VIDEO_PROVIDER=byteplus`, `BYTEPLUS_ARK_API_KEY` to a valid ModelArk key with activated access to the configured Seedance 2.5 model in the documented AP Southeast endpoint, and retain the exact official HTTPS `BYTEPLUS_ARK_BASE_URL`. The [official guide](https://docs.byteplus.com/en/docs/ModelArk/seedance-2-5) also calls for suitable resource pack or balance. Use an isolated test workspace and owned reference image. Check Job, ProviderExecution, external ID, stored READY artifact, checksum, and authorized preview/download. Do not run a paid call until credentials are supplied. `BYTEPLUS_SEEDANCE_QUALITY_MODEL` is not a runtime override: the reviewed model ID and policy version live in the server-owned `provider_configurations` row.

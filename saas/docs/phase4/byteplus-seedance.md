# BytePlus ModelArk: Dreamina Seedance 2.5

The configured model is `dreamina-seedance-2-5-260628`, from the [official Seedance 2.5 guide](https://docs.byteplus.com/en/docs/ModelArk/seedance-2-5). The verified API origin is `https://ark.ap-southeast.bytepluses.com` (AP Southeast); the adapter accepts only this HTTPS origin, even if `BYTEPLUS_ARK_BASE_URL` is set. Deployment/account region eligibility still needs a credentialed acceptance check. An API key is sent as a server-side Bearer header.

The [create task API](https://docs.byteplus.com/en/docs/ModelArk/create-video-generation-task-api) uses `POST /api/v3/contents/generations/tasks`. This implementation sends text plus up to four `reference_image` `image_url` items, `omni_reference_task_type=reference`, duration, ratio, 720p resolution, MP4 output, and audio disabled. The guide documents 4–30 seconds and ratios including `9:16`, `16:9`, and `1:1`; the UI offers these confirmed values. The API permits 1–30 reference images for this model, but this initial policy limits requests to four. It does not send supported video or audio references because those modes need separate validation. Each selected private Product image is read server-side, checked against the frozen size and SHA-256, then sent as a Base64 data URL. The storage bucket stays private; no long-lived signed reference URL is shared.

The [retrieve/list task API](https://docs.byteplus.com/en/docs/modelark/list-video-generation-tasks-api) reports queued, running, succeeded, failed, and cancelled states. The server polls the stored task ID and copies the successful `content.video_url` into its own private object storage because the provider URL is temporary (documented as valid for 24 hours with a download count limit). The adapter accepts only HTTPS output URLs on permitted BytePlus/Volces host suffixes and does not follow redirects.

The [task deletion API](https://docs.byteplus.com/en/docs/modelark/1521720) documents cancellation for queued tasks. A customer request while a task is running remains a cancellation request until the provider outcome is known; success may still arrive. The [video tutorial](https://docs.byteplus.com/en/docs/modelark/video-generation-tutorial?redirect=1) describes callbacks, but Phase 4 uses polling because it has a durable external task ID and does not depend on callback authentication.

The consulted official task documentation did not identify a provider-side idempotency key for task creation or a reliable lookup by a client submission token. The adapter therefore persists `SUBMITTING` before HTTP submission. Any timeout, server error, or response without a task ID becomes `SUBMISSION_UNKNOWN` / Job `RECONCILING`; it is never automatically resubmitted. The fake provider can recover its deterministic original task. Real uncertain submissions require provider/account reconciliation or support. No second billable task is created merely because an HTTP response was lost.

The [official ModelArk pricing page](https://docs.byteplus.com/en/docs/modelark/model-pricing?redirect=1) says Seedance 2.5 pricing depends on output resolution and whether video is included in the input. This implementation sends image references and 720p output but does not estimate cost or add customer billing. The [Seedance guide](https://docs.byteplus.com/en/docs/ModelArk/seedance-2-5) says the account must have model access and a suitable resource pack or balance; it recommends more than USD 30 balance or a USD 30 savings plan. The actual BytePlus API call has not been exercised without a configured account key. One short, single-output real acceptance generation is the next credentialed check after the nonbillable suite passes.

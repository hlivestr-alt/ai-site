# Product reference assets

Purposes are FRONT, BACK, LEFT_SIDE, RIGHT_SIDE, PACKAGING, CAP_PUMP, TEXTURE, USAGE_IMAGE, USAGE_VIDEO, PRODUCT_VIDEO, and OTHER. Multiple assets may share a purpose. JPEG, PNG and WebP images and MP4 video are accepted. MOV is not accepted. Default size limits are 20 MiB per image and 500 MiB per video, configurable via `MAX_IMAGE_BYTES` and `MAX_VIDEO_BYTES`. The video limit supports practical reference footage without sending it through Next.js; it still bounds local storage cost. Zero-byte uploads and unsupported content are rejected.

Every `assets` row has a permanent Product and workspace. `asset_versions` records the original display filename, generated upload/final keys, type, declared and verified sizes, optional expected and verified SHA-256, rights source type, permission note, confirmation time, uploader, status, and image dimensions/thumbnail key. Source types are CUSTOMER_UPLOAD, CUSTOMER_OWNED, LICENSED, CREATOR_AUTHORIZED and OTHER. Filenames never form storage keys. No cross-workspace deduplication or existence signal exists.

The browser requests an upload intent, uploads directly to a five-minute signed staging URL, and calls finalize. Finalize checks object existence, declared size/type, byte count, file signature and optional expected SHA-256; for images it decodes dimensions with a pixel bound and creates a JPEG thumbnail. It copies the verified original to a generated version key and records `READY`. Video signature is checked; duration and dimensions are left null because no video probe/worker is implemented in Phase 2. Video thumbnails are not claimed. A thumbnail failure leaves the verified original ready with `THUMBNAIL_FAILED` and no thumbnail.

State is `PENDING_UPLOAD`, `READY`, `FAILED`, or `ARCHIVED` at the Asset level, and `PENDING_UPLOAD`, `READY`, or `FAILED` for each version. Missing upload can be retried during the pending period; a duplicate finalize returns success without duplicating the version. Validation mismatch marks that version failed. Replacement creates a new AssetVersion and changes the current pointer after verification, retaining the old ready version and object. A missing current object marks its Asset failed when download is requested. Archive is metadata-only and succeeds even if the object is absent; history remains. An administrator can inspect failures and create a new upload. Abandoned staging intents have an explicit [cleanup command](local-development.md).

# Workspace and role acceptance

Authenticated workflow APIs use requireActiveWorkspace plus existing requireRole. Definition, version history, Run, steps, children, review bindings, events, budget and results always require the selected workspace. Foreign substituted definition/run IDs return 404. VIEWER may list/detail definitions/runs but receives 403 on create, edit, archive, estimate, paid start, pause, resume, cancel and budget increase.

0008 composite FKs ensure DefinitionVersion belongs to Definition/workspace; Step belongs to Run/workspace; Job lineage matches Step/Run/workspace; child mapping references that exact Job tuple; and bound ContentVersion belongs to its producer Step/Run/workspace. Existing Content media/review permissions remain authoritative. Direct foreign mapping and lineage mutations are rejected by the database.

Unit tests exercise registry controls, bounded settings, deterministic fan-out, exact review policy, run requests and explicit production ceiling. Integration covers immutable versions/snapshots, concurrent starts/reconcilers, 100 replay ticks, real process crashes at admission boundaries, fresh child quotes, price changes, wallet/budget waits, controls, failure/review outcomes, Content binding, a terminated/restarted deterministic fixture worker process, worker fencing and financial lifecycle. Substituted workflow-produced Content IDs are denied for detail, exact-version media and review. Browser coverage creates/edits recipes, closes the browser, reviews exact outputs and inspects desktop/mobile run screens. Phase 1–7 tests remain required.

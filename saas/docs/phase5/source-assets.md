# SourceAssets and upload integrity

SourceAssets are immutable workspace-owned source MP4s, separate from Product reference Assets. States: PENDING_UPLOAD → UPLOADED → VERIFIED, with FAILED/ARCHIVED reserved for failure/retirement. Only finalized UPLOADED/VERIFIED sources can enter a job. VERIFIED records SHA-256 and video geometry after the first authenticated worker downloads/probes the complete sealed source.

MAX_CLIPPER_SOURCE_BYTES defaults to 10 GiB, capped at 100 GiB by runtime and database. Sources under or equal to 64 MiB use a direct signed PUT; larger ones use S3 multipart, 64 MiB parts. Neither passes source bytes through Next.js memory. The API issues one part URL at a time (15 minutes), lists uploaded parts from storage, and completes only an exact contiguous set with expected per-part sizes. Browser retries individual parts three times and keeps a workspace/file resume handle in localStorage. Reselecting the original file resumes completed parts; file name/size/mtime and first/last 64 KiB digest identify the local handle. This is an upload-resume hint, not a full-file integrity checksum.

Staging: pending/workspaces/<workspace>/sources/<id>/upload. Sealed private source: workspaces/<workspace>/sources/<id>/original. Filenames never determine keys. Finalization copies the completed staging object under an ETag condition to a distinct object never exposed through signed PUT. Copy above 5 GiB uses multipart server-side copy in 256 MiB ranges. Replay of an old staging URL cannot mutate a finalized source. Retried finalization returns the existing source. The database prevents immutable identity and finalized checksum changes.

Finalize checks byte count, declared MIME and MP4 signature, not a full multi-GB probe. Worker performs ffprobe, checks audio, computes SHA-256 while streaming download to .partial, compares size and any previous checksum, and atomically renames. Multipart ETag is never treated as SHA-256. First successful source/verify callback pins the digest; subsequent attempts compare it. Video duration is bounded below 24 hours, dimensions at 16384. Failed partial uploads do not execute. Explicit abort is available for pending uploads; deploy a storage lifecycle for abandoned pending objects/incomplete multipart uploads. Bucket stays private; all API access requires current workspace membership.

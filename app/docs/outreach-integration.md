# Outreach integration (Phase 2)

The existing Outreach API runs on local port 4000, web interface on 3000, and PostgreSQL on 5432. Its campaign list/detail GET handlers call `expireFrozenCampaigns` before reading, so those endpoints can update campaign state. They are unsuitable for Phase 2's strict no-write requirement. AI Site uses a server-only PostgreSQL adapter in `src/lib/integrations/outreach/` instead. No existing repository, schema, or service was changed.

Set `OUTREACH_DATABASE_URL` only in the platform server environment. The adapter accepts only a local PostgreSQL address, opens `BEGIN READ ONLY`, runs one SELECT, and commits. It returns the latest 100 campaigns, target and creation metadata, frozen recipient counts, and sending counts. It never selects message text, creator records, credentials, or recipient identities. `/api/outreach/overview` returns only these sanitized aggregates. The browser receives no database URL.

Counts follow `apps/api/src/outreach/outreach.service.ts` in the native repository: recipients must be `selected=true` with `frozenMessage` present. Remaining is frozen minus terminal `SENT`, `RESTRICTED`, `FAILED`, `DELIVERY_UNKNOWN_UNRESOLVED`, and `CANCELLED`. `DELIVERY_UNKNOWN` is displayed together with unresolved unknowns but remains non-terminal until resolved. `PROCESSING` maps to “Sending.” Campaign state tabs mirror native state names; no campaign or sending controls are exposed.

Live validation connected in read-only mode and returned 44 campaigns. The latest campaign had 500 frozen, 497 sent, 3 restricted, and 0 remaining, agreeing with the native service's calculation. Unit tests verify the read-only transaction sequence and terminal arithmetic. We did not call the native list/detail endpoints because their GET handlers may write. A dedicated PostgreSQL account limited to SELECT would strengthen the deployment boundary; the adapter's transaction is currently the enforced read-only guard. The local server environment file is ignored by Git and contains the connection setting, never browser-exposed.
